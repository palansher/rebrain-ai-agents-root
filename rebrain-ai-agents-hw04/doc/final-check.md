# Финальные ньюансы

**Прочее (важные нюансы)**

1. **`.env` не в `.gitignore`.** `uv init --bare` создал `.gitignore` — проверь, что `.env` там **не** упомянут, а `.venv/` — упомянут. Скажи агенту об этом в Шаге 1.
2. **Модель SpaCy в Docker.** `ru_core_news_sm` не ставится через `uv add spacy` как обычный пакет — её надо докачивать отдельной командой в Dockerfile: `RUN uv run python -m spacy download ru_core_news_sm`. Иначе воркер упадёт на старте. Это прописано в Шаге 4.
3. **`init.sql` и volume.** Скрипт выполняется Postgres **только при первом** старте с пустым volume. Если меняешь схему — `docker-compose down -v` перед `up`.
4. **Порядок запуска.** В шагах 1–3 поднимай только нужные сервисы (`docker-compose up redis postgres monitor`), воркер — с шага 3. Так проще локализовать ошибки.
5. **Методический раздел README.** В конце задания требуют зафиксировать наблюдения: что планировала дорогая модель (Plan), что генерировала дешёвая (Act), где помогли checkpoints. Заполни заготовку в README после сдачи — это формальный критерий готовности.
6. **`/refresh` и дедупликация.** Ключевой тест: вызвать `/refresh` дважды подряд — второй раз `new_items` должен быть `0` (или близко к нулю, если за это время реально вышла новость). Это доказывает, что дедупликация работает.
